# PVC2609 关键位层级与自动发布 sanity check

## 背景

2026-06-29 上午盘开盘前报告曾把 `4475-4495` 提前作为当日上午盘近端压力区。群内用户指出：上周五正式复盘给出的压力是 `4400-4410`，而 `4475` 只有日线级别大反抽才可能触及。复核后确认这是生成器的关键位层级错误。

## 根因

`pvc2609_generate_session_report.py` 在推导下一时段关键位时，曾将全量历史 15m K 线传入 `derive_levels(...)`：

```python
derive_levels(session_summary, quote, klines.get(15, []))
```

这会把历史远端压力或日线级别修复位混入“下一时段近端压力”，导致远端压力近端化。

## 固化修正

生成下一时段计划时，关键位必须只从被复盘时段的 15m K 线推导：

```python
session_rows_15m = bars_for_session(klines.get(15, []), args.date, args.session)
levels = derive_levels(session_summary, quote, session_rows_15m)
```

含义：

- 午盘预测：用上午盘结构推导午盘关键位。
- 夜盘预测：用完整日盘结构推导夜盘关键位。
- 次日日盘预测：用夜盘结构推导次日初始关键位，并结合日K背景标注远端位。

## Sanity check 规则

自动发布前应拦截明显不合理的近端压力：

- 从报告中读取复盘时段高点、收盘价、近端压力下沿。
- 如果“近端压力下沿”同时高于复盘高点与收盘价超过约 50 点，应阻止自动发布，提示人工复核。
- 远端位可以保留，但必须标注为“远端强反抽 / 日K修复门槛”，不能写入“近端压力”。

示例拦截文案：

```text
关键位 sanity check failed：近端压力 4475 距复盘高点 4393 / 收盘 4382 超过50点，疑似把远端压力误作近端压力，已阻止自动发布
```

## 复核口径

当用户或群内质疑压力位过高时，不要先辩解。应按以下顺序复核：

1. 查前序正式复盘文档中的关键位链条。
2. 查当前时段实际 K 线区间、高点、低点、收盘。
3. 判断该点位属于：近端压力、核心压力、修复观察、远端强反抽、还是日K级别门槛。
4. 若远端位被写成近端位，应承认生成/复核错误，并立即：
   - 给本地正式报告加更正说明；
   - 更新 `runtime/pvc2609_feishu_monitor/latest_prediction_levels.json`；
   - dry-run 下一个将自动发布的午盘/夜盘报告；
   - 若生成器有同类风险，修生成逻辑和发布前 sanity check。

## 表达模板

群内可用简洁口径：

```text
这里是我这边文档生成和复核的问题。该点位属于日K级别远端强反抽/修复门槛，不应作为当前时段近端压力。当前更合理的链条是：近端压力 X-Y，核心压力 A-B，修复确认 C；远端位只保留为强修复观察，不作为第一做空参考。文档和监控关键位已修正。
```

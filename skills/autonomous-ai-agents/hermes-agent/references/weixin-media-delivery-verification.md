# 微信媒体附件发送与校验

## 适用场景

用户反馈“图片没收到”“附件没有显示”，或助手准备通过 Hermes Weixin 网关发送本地图片/文件时。

## 关键分层

1. **产物层**：图片或文件是否真实生成，路径是否存在，内容是否完整。
2. **回复解析层**：最终回复是否确实包含 `MEDIA:<absolute_path>`，而不只是“已发送”的文字。
3. **网关发送层**：日志是否完成媒体上传/发送，而非仅出现 `Sending image`。
4. **微信接收层**：平台是否返回成功，用户端是否可见。

不得用文字消息发送成功推断附件也成功。

## 标准流程

1. 使用宿主机上的持久绝对路径保存最终产物，例如：
   `~/.hermes/generated/<name>.png`。
2. 在发送前确认：
   - 文件真实存在；
   - 文件类型、尺寸或内容符合预期；
   - 路径是网关宿主机可访问的路径。
3. 不直接转发图像生成服务、沙箱或容器返回的临时路径。典型风险路径包括 `/mnt/data/...`；它可能只存在于上游运行环境，不存在于网关宿主机。
4. 通过 `send_message` 发送，消息中显式包含：
   `MEDIA:/absolute/host/path/to/file.png`
5. 以 `send_message` 返回的 `success: true` 和 `message_id` 作为当前发送路径成功的主要证据。
6. 若用户仍未收到，读取最新网关日志，查找同一时间附近的：
   - `Sending image`
   - `send_document failed`
   - `Failed to send image`
   - `No such file or directory`
   - 平台上传或 iLink 错误
7. 修复后必须重新附带 `MEDIA:` 发送；只回复“已重新生成”不会自动重试上一条附件。

## 常见误判

- `Sending response` 只说明文字回复正在发送。
- `Sending image` 只说明媒体发送动作开始，不代表完成。
- 输入框或聊天中出现“已发送”文字，不是媒体成功证据。
- 重新生成文件后，如果最终回复没有 `MEDIA:`，微信仍只会收到文字。
- 不存在的路径不能靠重复发送恢复；应先换成网关宿主机上的有效路径。

## 最小用户说明

失败时直接说明已确认的原因，例如：

> 上一次引用的是网关本机不存在的临时路径，因此文字到了，但图片上传失败。我已换成有效的本机绝对路径重新发送，并取得消息 ID。
